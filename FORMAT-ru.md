# 📊 Выходной формат `arcella-inspect`

Утилита `arcella-inspect` (часть экосистемы **Arcella**) выполняет статический анализ Rust-проектов и генерирует структурированную метаинформацию о коде в виде иерархического **YAML 1.2**-документа. Этот формат оптимизирован для последующей обработки AI-агентами, системами анализа зависимостей, генераторами документации и инструментами архитектурного аудита.

## 🧭 Общие принципы

1. **Валидность**: выходной документ — строго валидный YAML 1.2.
2. **Иерархия**: функции и их вызовы представлены декларативно, с сохранением локальных и полных имён.
3. **Идентификация**: каждый элемент (функция, структура) имеет уникальное имя и сопутствующие метаданные (файл, строка).
4. **Подпроекты**: поддержка Cargo workspaces — каждый член workspace обрабатывается как независимый подпроект.
5. **Метаданные**: для каждого элемента сохраняются:
   - путь к файлу (относительно корня подпроекта),
   - номер строки,
   - тип (`function`, `struct`),
   - атрибуты, сигнатура, документация.

---

## 🗂 Структура выходного YAML

```yaml
version: "1.0"                     # Версия формата arcella-inspect
project_name: "my-platform"        # Имя основного проекта (опционально)
subprojects:
  - name: "auth-service"           # Имя подпроекта (из Cargo.toml `package.name`)
    root: "crates/auth/"           # Путь от корня анализа до корня подпроекта
    structures:
      - name: "AuthState"
        file: "src/state.rs"
        line: 8
    functions:
      - name: "validate_token"
        file: "src/validator.rs"
        line: 34
        returns: "Result<Claims, AuthError>"
        parameters:
          - "token: &str"
          - "secret: &[u8]"
        docstring: "Проверяет JWT-токен с заданным секретом."
        attributes:
          - "pub"
          - "async"
        calls:
          - name: "jsonwebtoken::decode"
            external: true
          - name: "metrics::record_auth_attempt"
            file: "src/metrics.rs"
            line: 12
    # (опционально) плоский список вызовов — для упрощённого анализа графов
    edges:
      - from: "validate_token"
        to: "metrics::record_auth_attempt"
```

## 🧱 Детали формата

### 1. `version`

- Тип: строка
- Значение: `"1.0"`
- Назначение: обеспечивает обратную совместимость при будущих изменениях формата.

### 2. `project_name` (опционально)

- Берётся из `workspace.package.name` или корневого `Cargo.toml`.
- Может отсутствовать — в этом случае `subprojects` несут полную идентификацию.

### 3. `subprojects[]`

Каждый подпроект соответствует отдельному crate в workspace или standalone-проекту.

| Поле       | Обязательность | Описание |
|------------|----------------|--------|
| `name`     | ✅             | Имя крейта (`package.name` из `Cargo.toml`) |
| `root`     | ✅             | Относительный путь от корня анализа до его корня |
| `structures`| ❌             | Список структур |
| `functions`| ✅             | Список всех функций и методов |
| `edges`    | ❌             | Плоский список вызовов (для графовых анализаторов) |

---

### 4. Элемент `structures[]`

| Поле   | Обязательность | Описание |
|--------|----------------|--------|
| `name` | ✅             | Имя структуры (`struct MyStruct`) |
| `file` | ✅             | Путь относительно `root` подпроекта |
| `line` | ✅             | Номер строки определения |

> Трейты, перечисления и модули могут быть добавлены в будущих версиях.

---

### 5. Элемент `functions[]`

| Поле         | Обязательность | Описание |
|--------------|----------------|--------|
| `name`       | ✅             | Полное имя: `module::MyStruct::method` или `free_function` |
| `file`       | ✅             | Путь относительно `root` |
| `line`       | ✅             | Строка определения |
| `returns`    | ✅             | Строковое представление возвращаемого типа (`"Result<(), Error>"`) |
| `parameters` | ❌             | Список аргументов: `["config: &Config", "ctx: &Context"]` |
| `docstring`  | ❌             | Текст `///`-комментариев без префиксов, с сохранением переносов |
| `attributes` | ❌             | Список: `"pub"`, `"async"`, `"unsafe"`, `"const"`, `"#[test]"`, `"#[instrument]"` и т.д. |
| `calls`      | ✅             | Список вызываемых функций (см. ниже) |

---

### 6. Элемент `calls[]` (внутри функции)

| Поле      | Обязательность | Описание |
|-----------|----------------|--------|
| `name`    | ✅             | Полное имя вызываемой функции (`tokio::time::sleep`, `self::helper`) |
| `file`    | ❌             | Только если вызов **внутренний** (определён в том же проекте) |
| `line`    | ❌             | Только если `file` указан |
| `external`| ❌             | `true`, если вызов из внешнего крейта (`std`, `tokio`, `serde` и т.д.) |

> Если `external: true`, поля `file` и `line` **не указываются** (или игнорируются при парсинге).

---

### 7. Плоский список `edges[]` (опционально)

Для упрощённого построения call graph:

```yaml
edges:
  - from: "auth::validate_token"
    to: "metrics::record_auth_attempt"
  - from: "auth::validate_token"
    to: "jsonwebtoken::decode"
```

- `from` и `to` — полные имена функций.
- Может использоваться инструментами, не желающими парсить вложенные структуры.

## 🔍 Пример минимального валидного вывода

```yaml
version: "1.0"
subprojects:
  - name: "hello"
    root: "."
    functions:
      - name: "main"
        file: "src/main.rs"
        line: 1
        returns: "()"
        attributes:
          - "pub"
        calls:
          - name: "println!"
            external: true
```

## ⚙️ Замечания для реализации (внутренние)

- Анализ основан на **AST** через `syn`, а не на MIR или HIR — это обеспечивает точное соответствие исходному коду.
- Параметры и возвращаемые типы сериализуются **как есть**, без нормализации компилятором.
- `docstring` собирается из всех `#[doc = "..."]` и `///` строк и объединяется с `\n`.
- Атрибуты включают как **языковые ключевые слова** (`pub`, `async`), так и **атрибут-макросы** (`#[cfg(...)]`, `#[instrument]`).
- Внешние вызовы определяются по отсутствию в индексе функций текущего подпроекта.

## 🧩 Расширяемость

Формат спроектирован с учётом будущих улучшений:

- Добавление `tags: ["hot-path", "security-critical"]`
- Аннотации от AI-агентов (`ai_summary: "Auth validator"`)
- Поддержка трейтов, impl-блоков, констант
- Интеграция с профилировщиками (`avg_latency_ms: 12.4`)

Все новые поля будут **опциональными** и не нарушат совместимость.
